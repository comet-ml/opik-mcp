# Examples

**Set up after instrument.** `/opik-loop` on `support-agent`, traces landing, a `resolution` judge already live. `list('recommendation')` ranks Collect first: "Nothing adds production failures to a test suite. 1,240 traces scored resolution in 14 days, 189 below 0.5." Dry run of `workflow.enable` with `recipe: "collect"` shows one automation, "Low-resolution traces to the suite": `feedback_score:created` where `resolution < 0.5` → `test_suite.add` into `Regression · support-agent` (created), estimate `fired 1,240, items 189, cost $0`. User says yes; the live call creates it; `list('automation')` shows it enabled. → **`on`**, `check_in_suggested: true`; next step = "in a week, ask what changed in the loop".

**Gate on PRs.** `/opik-loop gate my PRs on the regression suite` on `support-agent`, Collect on for three weeks, 44 cases in `Regression · support-agent`. `list('workflow')` lists `gate` with `prerequisites_met: true`. Asked, the user names the prompt `support-answer` and the model `gpt-4o-mini`, the repository `example-org/support-agent`, and a Slack webhook URL. Dry run of `workflow.enable` with `recipe: "gate"` and those overrides: `would_create: ["Test new versions"]` — `prompt:committed` or `ci:run` → `test_suite.run` on the suite → `github.check` → `notify` only if `run.regressions > 0` — estimate `fired 11, cost $4.20`, `limits.max_cost_usd_per_day: 5` proposed, and `setup.github_action`. The step goes into `.github/workflows/opik-gate.yml` as a change for review, `OPIK_API_KEY` read from the repo's secrets. User says yes; the live call creates it; `list('automation')` shows it enabled. → **`on`**, `setup.path: .github/workflows/opik-gate.yml`; next step = "merge the CI change; the first run lands as `pending` on the next PR".

**Gate failed on PR 482.** `/opik-loop why did Gate fail on PR 482`. `list('automation_run', automation_id=…, status='done')` → the row whose `item_id` is `example-org/support-agent@9f3c2d1`. `read('automation_run', id)`: `outputs.run.regressions: 2`, `run.pass_rate: 0.9` against `run.baseline_pass_rate: 0.95`; step `check` posted `failure`, `notify` done; `parent_run_id: null` (CI fired it). → **`explained`**; next step = "`/opik-compare` with `run.experiment_id` and `run.baseline_experiment_id` for the two cases that regressed". (A sibling run still `pending` with `waiting_on: experiment:finished:<id>` has not failed: its suite run is not finished.)

**Gate, code agent.** The same ask on an agent Opik cannot run (tools, retrieval, its own code). The dry run says `test_suite.run` is for prompt targets, so the automation is a custom one: trigger `{"event": "experiment:finished", "test_suite_name": "Regression · support-agent"}`, steps `github.check` and `notify`; CI runs the suite with the SDK and calls the CI endpoint. `automation.create` dry run, the CI change for review, create on yes. → **`created`**.

**Improve after Gate.** `/opik-loop improve the prompt as the suite grows` on `support-agent`, Collect and Gate on, 61 cases in the suite. `list('loop')` shows `production → Regression · support-agent` (collect, 62 items in 14 days) and `support-answer → the suite, the repository` (gate, 11 runs); nothing writes the prompt. `list('workflow')` lists `improve` with `prerequisites_met: true`. Asked, the user names the prompt `support-answer` and the model `gpt-4o-mini`; `n: 50`, `min_gain: 0.05`, `metric: levenshtein_ratio`, `optimizer: hierarchical_reflective` stay the defaults, `limits.max_cost_usd_per_day: 10` proposed. Dry run of `workflow.enable` with `recipe: "improve"`: `would_create: ["Optimize support-answer as the suite grows"]` — `test_suite:grew` by 50 → `optimizer.run` → `prompt_version.save` only if `optimize.gain >= 0.05` — and no estimate (a counted trigger has nothing to replay), said as such. The answer explains that a saved version is a `prompt:committed` event Gate then tests, and that the optimizer needs Opik's python backend worker. User says yes; the live call creates it; `list('automation')` shows it enabled. → **`on`**; next step = "after the next 50 cases, read the improve run: `pending` while it optimizes, then `optimize.gain` and, when it gained enough, `save.commit`".

**Improve did not save.** `/opik-loop why did Improve not save a version`. `list('automation_run', automation_id=…)`: the latest run is `done`, `save` is `skipped`, `outputs.optimize.gain: 0.02` against `min_gain: 0.05` (`best_score 0.80`, `baseline_score 0.78`). Nothing failed: the gain was too small to keep. → **`explained`**; next step = "lower `min_gain` with `automation.update` if 2% is worth a version, or let the suite grow". (A sibling run `failed` with `last_error: timed out after PT24H waiting` is the optimizer never finishing: the python backend worker, a blocker.)

**Align's second half.** `/opik-loop is the judge still right` on a project where `align` is `partly_on`: reviewers have scored 40 traces in `Judge review`, nothing compares their verdicts with the judge's. Asked, the user names `resolution`; `n: 20`, `threshold: 0.5` stay, a Slack webhook is given. Dry run of `workflow.enable` with `recipe: "align"`: `would_create: ["Check resolution against reviewers"]` — `annotation_queue:submitted` every 20 reviews → `judge.agreement` → `judge.revise` only if `agreement.agreement < 0.8`; the answer says `judge.revise` is a notification carrying the agreement and the disagreements, not a change to the judge. User says yes; the live call's `created` carries the new automation beside the sample one. → **`on`**; next step = "after 20 more reviews, read `outputs.agreement.agreement` and `compared`; below 0.8, `/opik-online-eval` revises the judge".

**A tune recommendation applied.** `/opik-loop what should I do next` on a project whose Collect automation hit `max_items_per_day` and is paused. The top row is `tune` with `automation_id` set: "'Low resolution traces to the suite' hit its max_items_per_day limit and is paused until midnight. Raise max_items_per_day to 400, or tighten the threshold so fewer traces match." `apply_call` = `write('automation.update', data={"automation_id": "…", "limits": {"max_items_per_day": 400}})`. Shown: the limit goes from 200 to 400 and the automation resumes at midnight. Dry run, then user says yes, then the live call. → **`applied`**; next step = "check `items_7d` next week; a suite growing by 400 a day may want a tighter threshold instead".

**A remove recommendation applied.** The top row is `remove`: "Every step of 'Check resolution against reviewers' failed in 14 days (2 failures). Disable it until the target is fixed." `list('automation_run', automation_id=…, status='failed')` shows `last_error: "queue not found"` — the queue was deleted. `apply_call` = `write('automation.disable', data={"automation_id": "…"})`; shown, agreed, sent (no backend dry run for a disable). → **`applied`**; next step = "recreate the queue or re-point the step with `automation.update`, then `automation.enable`".

**Next step applied.** `/opik-loop what should I do next` on a project with Collect on for 20 days. Top recommendation is upkeep: "Collect added 310 cases in 14 days", `apply_call` = `write('automation.update', data={"automation_id": "…", "limits": {"max_items_per_day": 100}})`. Dry run shows the estimate at the new cap; user says yes. → **`applied`**; next step = "check the suite's growth next week".

**Worth it, answered from the stats.** `/opik-loop is Collect still worth it`. `read('automation', id)`: `stats` = fired 2,100, sampled 2,100, items_written 44, cost $0; `paused_reason: null`; no recommendation names it. Answer: 44 cases a week into the suite at no cost, nothing to change. → **`explained`**; next step = "run `/opik-compare` on the suite before the next prompt change".

**Failed run explained.** `/opik-loop why did this automation fail`. `list('automation_run', automation_id=…, status='failed')` → one hourly rollup; `read('automation_run', id)`: step `keep` failed 12 of 12 with `last_error: "suite not found"`, `parent_run_id: null`. The suite was deleted. → **`explained`**; next step = "re-point the step at an existing suite with `automation.update`, or recreate it with `/opik-test`".

**Custom automation, tested first.** `/opik-loop send refund answers below 0.5 to review`. Dry run of `automation.create`: trigger `feedback_score:created` on `resolution < 0.5` with `per_day: 10`, step `annotation_queue.add` into `Refund review` (created), limits none needed (no step costs money), estimate `items 10/day`. `automation.test` on a recent refund trace returns step `add` as `done`. User says yes. → **`created`**; next step = "annotate the first few in the queue, then `/opik-loop` again for Align".

**Blocked — no backend.** `list('recommendation')` is refused: this Opik has no automations yet. → **`blocked`**: "it needs a backend version that ships automations; `list('online_rule', …)` still shows the judges." (Nothing written.)

**Blocked — optimizer worker.** The improve run stays `pending` on `waiting_on: optimization:finished:<id>` and the previous one is `failed` with `last_error: timed out after PT24H waiting`. → **`blocked`**: "the optimizer runs on Opik's python backend worker, which this Opik does not run; ask whoever runs it to enable the worker, and the next suite growth fires Improve again." (Nothing written, nothing retried.)

**Blocked — no GitHub token.** The live `workflow.enable` for Gate is refused with `integration_required`. → **`blocked`**: "set the workspace's GitHub token yourself with `PUT /v1/private/automations/integrations/github`; it never goes through this conversation. Then rerun `/opik-loop gate`." (Nothing written; the token is never asked for.)
